## Issue 1: Timestamp Extraction Returns Garbled Text

### Problem
- Timestamp OSD extraction was returning corrupted output like "01-04 F5t EEL 5h ed i ee..." instead of clean "DD-MM-YYYY HH:MM:SS"
- Root cause: Code was looking for `result.osdText` but Gemini API returns `result.timestamp`
- This caused the timestamp field to be empty, failing regex matches in parseOSDTimestamp

### Solution
**File: `services/aiServer.js` (line 516)**

**Before:**
```javascript
const osdText = String(result.osdText || '').trim();
```

**After:**
```javascript
// Gemini returns 'timestamp' field with the extracted date/time
const osdText = String(result.timestamp || '').trim();
```

## Issue 2: Only 2 Fotogramas Displaying Instead of 3

### Problem
- InfractionModal expects 3 fotogramas labeled ENTRADA, CRÍTICA, and SALIDA
- Only 2 frames were displaying (missing one phase capture)
- Issue was in `selectTriplet` function not properly selecting frames

### Solution
**File: `services/ForensicQueueV3.ts` (lines 281-299)**

Improved `selectTriplet` logic:

**Before:**
```typescript
private selectTriplet(frames: string[] = [], fallback: string[] = []): string[] {
  const source = frames.length > 0 ? frames : fallback;
  if (source.length === 0) return [];
  if (source.length === 1) return [source[0], source[0], source[0]];
  if (source.length === 2) return [source[0], source[1], source[1]];
  return [source[0], source[Math.floor(source.length / 2)], source[source.length - 1]];
}
```

**After:**
```typescript
private selectTriplet(frames: string[] = [], fallback: string[] = []): string[] {
  const source = frames.length > 0 ? frames : fallback;
  if (source.length === 0) return [];

  // Always return exactly 3 frames for fotogramas display (ENTRADA, CRÍTICA, SALIDA)
  if (source.length === 1) {
    return [source[0], source[0], source[0]];
  }
  if (source.length === 2) {
    return [source[0], source[1], source[1]];
  }

  // For 3+ frames, select: first (entrada), middle (crítica), last (salida)
  const midIndex = Math.floor((source.length - 1) / 2);
  return [source[0], source[midIndex], source[source.length - 1]];
}
```

**Key improvements:**
- Calculates middle index correctly: `Math.floor((source.length - 1) / 2)` instead of `Math.floor(source.length / 2)`
- This ensures proper frame selection when we have 3, 4, 5+ frames
- Always returns exactly 3 frames for display

## Data Flow Verification

### Evidence Capture Flow
1. **EvidenceCaptureManager** captures snapshots at 3 phases:
   - ROI_A: Vehicle enters forbidden turn zone
   - MID: Vehicle in transition/middle path
   - ROI_B: Vehicle completes forbidden turn (infraction confirmed)

2. Each phase captures 2 images:
   - General frame (full scene context)
   - Detail frame (vehicle crop for plate OCR)

3. Evidence saved with:
   ```
   contextSnapshots: [roi_a_general, mid_general, roi_b_general] // 3 images
   zoomSnapshots: [roi_a_detail, mid_detail, roi_b_detail] // 3 images
   ```

### Forensic Processing
1. **ForensicQueueV3** retrieves evidence from database
2. Uses `selectTriplet()` to select 3 context frames
3. Sets `extraSnapshots = contextSnapshots` in InfractionLog
4. **InfractionModal** receives log and displays 3 fotogramas

### Result Display
```
FOTOGRAMA 01 (ENTRADA EN ROI)       → extraSnapshots[0]
FOTOGRAMA 02 (POSICIÓN CRÍTICA)     → extraSnapshots[1]
FOTOGRAMA 03 (SALIDA / CONFIRMACIÓN) → extraSnapshots[2]
```
