## Project Overview

Sentinel AI is a real-time traffic violation detection system that combines MediaPipe object detection, Kalman-filter-based tracking (ByteTracker), and Google Gemini multimodal AI to identify, capture evidence of, and generate forensic reports for traffic infractions. The primary deployment target is Spanish-speaking law enforcement contexts (Daganzo de Arriba, Madrid).

## Environment Setup

Copy `.env.example` to `.env.local`. Required variables:

| Variable | Purpose |
|---|---|
| `GEMINI_API_KEY` | Google Gemini key — used **server-side** for AI calls |
| `GEMINI_MODEL` | Gemini model (default: `gemini-2.5-flash`) |
| `PORT` | Express server port (default: `3002`) |
| `REPORTS_DIR` | Where PDFs and video evidence are saved (default: `C:\Denuncias`) |
| `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` | Optional cloud sync |

The Vite dev server proxies all `/api` requests to the Express server (`localhost:3002`). Both must be running for AI features to work.

## Architecture

### Two-Server Design

```
Browser (Vite :3001)  →  /api proxy  →  Express (:3002)
      ↑                                        ↓
  React UI                              Gemini AI calls
  MediaPipe WASM                        Video transcoding
  IndexedDB                             PDF report saving
  Zustand stores                        IP camera proxying
```

The Vite dev server requires `Cross-Origin-Embedder-Policy: require-corp` headers (set in `vite.config.ts`) to enable SharedArrayBuffer for MediaPipe WASM.

### Detection Pipeline

```
Video Source
  → MediaPipe EfficientDet (useNeuralCore)
  → ByteTracker (Kalman filter multi-object tracking)
  → useFrameProcessor (geometry intersection checks)
  → EvidenceCaptureManager (snapshots + 20s circular video buffer)
  → ForensicQueueV3 (sequential immutable AuditJob pipeline)
  → Gemini /api/ai/audit
  → InfractionLog → EvidenceDB (IndexedDB) + PDF (server REPORTS_DIR)
```

### State Management

Two parallel state systems coexist:

1. **SentinelContext** (`context/SentinelProvider.tsx`) — the primary global state consumed by almost all components via `useSentinel()`. Each viewer instance has its own provider (see multi-viewer below).

2. **Zustand stores** (`stores/`) — layout, focused viewer, forensics queue stats, geometry, tracking. These are global (shared across viewers).

### Multi-Viewer Architecture

`MultiViewerGrid` renders 1–4 `SentinelViewer` instances. Each viewer:
- Gets its own `SentinelProvider` keyed by `viewerId` (a UUID)
- Manages independent video source, geometry, tracks, and infraction logs
- Sidebars portal into `#sidebar-root` / `#right-sidebar-root` DOM nodes and display only the **focused** viewer's data
- `ForensicQueueV3` uses an event-listener pattern; `SentinelProvider` filters events by `viewerId` to prevent cross-viewer contamination

### ForensicQueue Versioning

`ForensicQueue.ts` is **deprecated** — it's a thin backward-compatibility wrapper that delegates everything to `ForensicQueueV3`. New code should use `ForensicQueueV3` directly or via the `forensicQueue` singleton (which actually instantiates V3 internally). The V3 design uses immutable `AuditJob` snapshots: all evidence is frozen at capture time so subsequent track mutations don't affect audit results.

### Geometry System

Lines are stored as normalized coordinates (0.0–1.0 relative to video dimensions). Key `EntityType` values:

- `stop_line` / `forbidden` / `lane_divider` / `box_junction` / `pedestrian` / `bus_lane` — single-line detection
- `roi_general` — general region of interest (triggers audit on entry)
- `roi_turn` — **two-ROI sequential forbidden-turn detection**: ROI A arms the capture, ROI B confirms and finalizes. Defined by `violationKind: 'forbidden_turn_sequence'` + `roiSequenceIds`.

Geometry can be generated by Gemini from a video frame screenshot (`/api/ai/geometry`) or drawn manually by the operator via `GeometryEditor`.

### Infraction Lifecycle

1. `useFrameProcessor` detects a geometry crossing → calls `EvidenceCaptureManager.startCapture()`
2. Evidence (JPEG snapshots + OCR text + mp4 clip) accumulates in `EvidenceDB`
3. `ForensicQueueV3.enqueue()` creates a frozen `AuditJob` and queues it
4. Queue processes one job at a time: fetches evidence → sends to Gemini → parses `AuditResponse`
5. If `infraction: true`, emits to listeners → `SentinelProvider.addInfraction()` → appends to `logs[]`
6. `ReportService.generateAndSaveInfractionPdf()` is called automatically; path stored in `log.reportPath`
7. Operator reviews in `InfractionFeed` and calls `validateInfraction(id, 'validated' | 'rejected')`

### Preset System

Three orthogonal preset dimensions (all persisted to `localStorage`):

- **Detection preset** (`PresetType`): `scout | sentinel | warden | shadow` — controls `EngineConfig` (confidence threshold, NMS, frame skip, persistence)
- **Audit preset** (`AuditPresetType`): `flash | tactical | full | standard | neural | senior` — controls Gemini prompt verbosity/depth
- **Kinematic preset** (`KinematicPresetType`): `lite | full | heavy` — controls which MediaPipe model is loaded

### Testing Setup

Tests use Vitest + jsdom. Heavy dependencies (EvidenceDB, aiService, MediaPipe) are mocked in test files using `vi.mock()`. The setup file is `tests/setup.ts`. Tests do not require a running server.
